## 1. 背景与目标

### 1.1 背景

单店足浴/推拿门店目前依赖纸质台账或通用收银软件，存在房间状态混乱、排钟纠纷、漏单跑单、交班对账困难等问题。市面行业软件（天之星、西电蓝鸟、美萍、索易、纳客、点钟宝 SaaS、客刻云、Vi-Office Spa 等）已形成成熟的功能范式，本项目参照行业标准，为门店构建自己的数字化前台管理系统。

### 1.2 一期目标

跑通门店日常营业主闭环：

```
开单 → 上钟 → 到钟提醒 → 落钟/加钟 → 收银结账 → 交班对账
```

### 1.3 需求确认结论

| 决策点     | 结论                                                     |
| ---------- | -------------------------------------------------------- |
| 业态       | 足浴/推拿，排钟制（轮钟/点钟）                           |
| 目标终端   | 前台营业端（H5 + 支付宝小程序双端）                      |
| 计费方式   | 按项目一口价（上钟计业绩，不实时计费）                   |
| 一期闭环   | 开单 → 上下钟 → 收银 → 交班                              |
| 会员体系   | 二期（`vk-order` 预留 `member_id` 字段）                 |
| 支付方式   | 仅线下：现金 / 挂账 / 组合支付（预留在线支付扩展）       |
| 上下钟操作 | 前台代操作，技师暂无手机端                               |
| 门店规模   | 单门店（表结构预留扩展字段）                             |
| 首页       | `pages/index/index`（房态墙）                            |
| 后端形态   | 云对象，放 `service/manager/` 目录，文件名 `sys.` 前缀   |
| 服务项目表 | `vk-service`                                             |

### 1.4 分期路线

| 阶段 | 范围                                                                           |
| ---- | ------------------------------------------------------------------------------ |
| P0   | **一期**：基础资料、房态开单、排钟上下钟、收银结账、交班、简版日报             |
| P1   | 二期：会员体系（储值/折扣/积分/余额支付）、在线支付、预约管理、提成自动核算    |

## 3. 角色与权限

### 3.1 角色定义

| 角色     | 职责                                             | 一期 |
| -------- | ------------------------------------------------ | ---- |
| 前台     | 开单、排钟、上下钟、收银、交班                   | ✅   |
| 店长     | 前台全部权限 + 基础资料维护 + 报表 + 优惠审批    | ✅   |
| 老板     | 查看全部数据（只读）                             | ✅（可复用 admin） |
| 技师     | 手机端报钟、查业绩                               | ❌ 二期 |
| 财务     | 提成核算、工资发放、对账                         | ❌ 二期 |

### 3.2 权限实现（vk 框架内置机制）

- 云对象放 `router/service/manager/` 目录，文件名以 `sys.` 前缀（如 `sys.order.js`），框架按内置规则将其判定为 **sys 类型函数**：需登录，且经 `checkSysAuth` 校验角色权限
- 权限链路：admin 后台「权限管理」录入权限点 → 「角色管理」赋权给角色 → 「用户管理」给账号赋角色
- 一期需录入的权限点（支持通配符匹配）：

| 权限 url            | 说明                 | 授予角色     |
| ------------------- | -------------------- | ------------ |
| `manager/sys.*`     | 全部前台营业接口     | 店长、老板   |
| `manager/sys.room.*` `manager/sys.order.*` `manager/sys.cashier.*` `manager/sys.shift.*` `manager/sys.tech.*` | 营业操作接口 | 前台 |
| `manager/sys.service.*` | 项目维护         | 店长         |
| `manager/sys.report.*`  | 日报查看       | 店长、老板   |

- 开发调试期可用 role 含 `admin` 的账号（框架直接放行）

## 4. 功能需求（一期）

### 4.1 基础资料维护（设置页，店长权限）

#### 4.1.1 服务项目管理（`vk-service`）

- 列表展示：名称、分类、价格、时长、排序、状态
- 新增/编辑/删除/上下架
- 字段：`name` 名称、`category` 分类、`price` 价格（元）、`duration` 时长（分钟）、`sort` 排序、`status` 状态、`remark` 备注

#### 4.1.2 房间管理（`vk-room`）

- 列表展示 + 新增/编辑/删除
- 字段：`name` 名称、`room_type` 类型（足浴房/按摩房/床位）、`capacity` 容纳人数、`status` 状态、`sort` 排序
- 房间状态：`空闲` / `占用` / `打扫`（打扫状态可由结账时触发，手动切换清洁完成）

#### 4.1.3 技师管理（`vk-tech`）

- 列表展示 + 新增/编辑/删除
- 字段：`name` 姓名、`no` 工号、`level` 等级、`skill` 擅长项目、`status` 在岗状态（上班/休息/休假）、`queue_pos` 队列位置、`queue_type` 队列类型、`shift` 班次（早班/晚班）、`sort` 排序
- 排班考勤细节（报到/报走、请假单）二期

### 4.2 房态墙首页（`pages/index/index`）

- 顶部统计条：在住房间数、待结账数、排队技师数、今日营业额
- 房间卡片网格（按状态着色）：
  - 空闲：可点击开单
  - 占用：显示房号、已上钟项目、技师、起钟时间、倒计时
  - 打扫：显示清洁中，可一键置为空闲
- 快捷入口：钟房、交班、日报、设置
- 数据刷新：10–15 秒轮询房态接口（`sys.room/getBoard`），支持下拉刷新
- 点击占用房间 → 进入房间详情

### 4.3 房间详情（开单与上下钟操作，`pages/room/detail`）

#### 4.3.1 开单

1. 选择服务项目（可多选，来自 `vk-service` 上架列表）
2. 为每个项目指定技师：
   - **轮钟**：默认取轮钟队列首位技师，可手动改选
   - **点钟**：从技师列表直接指定，标记 `queue_type=点钟`
3. 确认开单 → 生成 `vk-order`（状态：消费中）+ `vk-order-item`（一口价快照），房间状态置为「占用」
4. 规则：同一房间同时只允许一张消费中的账单；开单需事务 + 状态条件更新，防重复提交

#### 4.3.2 消费明细操作

| 操作     | 说明                                                       |
| -------- | ---------------------------------------------------------- |
| 加项     | 追加服务项目并指定技师，追加明细                           |
| 换项目   | 未上钟的明细可换项目（重算价格快照）                       |
| 取消项目 | 未上钟的明细可取消；已上钟明细不可直接取消（需先落钟）     |
| 删除     | 全部明细取消后可取消整单（账单状态置已取消，房间释放）     |

#### 4.3.3 上下钟

| 操作     | 说明                                                                 |
| -------- | -------------------------------------------------------------------- |
| 上钟     | 明细状态 `待上钟 → 上钟中`，记录 `clock_start`，`clock_no` 累加       |
| 落钟     | 状态 `上钟中 → 已完成`，记录 `clock_end`；技师回轮钟队尾（`queue_pos` 置末） |
| 加钟     | 对上钟中的明细追加一钟：`clock_no + 1`，`clock_start` 更新为当前时间  |
| 换技师   | 上钟中可换技师：原技师回队尾，新技师入队并接管该明细                  |
| 到钟提醒 | 前端按 `clock_start + duration` 本地倒计时，到点弹窗 + 声音提醒       |

- 技师状态同步：`休息 → 上钟中 → 休息（回队尾）`

### 4.4 钟房（排钟调度，`pages/tech/index`）

- 技师卡片列表：头像/姓名、工号、状态（排队中/上钟中/休息/休假）、当前房间、已上钟数
- 轮钟队列：按 `queue_pos` 升序展示排队顺序
- 队列操作：
  - 置顶（奖头牌）、置尾（跳牌）、上移/下移手动调序
  - 指定点钟（从队列外直接选人上钟）
  - 暂停排队 / 恢复排队（休息）
- 队列变更实时生效于开单时的默认派工

### 4.5 收银结账（`pages/cashier/index`）

1. 从房间详情「结账」进入，展示账单明细（项目、技师、钟数、单价、小计）
2. 优惠：整单减免金额 / 折扣（店长权限可设，金额自动重算）
   - `total_amount` 消费合计 − `discount_amount` 优惠 = `pay_amount` 应收
3. 支付方式（一期线下）：
   - 现金：输入实收，自动算找零
   - 挂账：记录欠款（账单状态置已结账，支付类型为挂账）
   - 组合：多笔支付流水组合（如现金 + 挂账），每笔写入 `vk-order-pay`
4. 结账完成：
   - `vk-order.status → 已结账`，房间状态 → 打扫（或直接空闲，可配置）
   - 防重复结账：状态条件更新 + 事务
5. 二期扩展：会员余额支付、微信/支付宝在线支付

### 4.6 交班（`pages/shift/index`）

- 展示当班汇总（自上次交班至今）：
  - 开单数、结账单数、接待项目数
  - 现金应收、挂账金额、其他支付合计、消费总额
  - 优惠总额、减免总额
- 点钞核对：输入现金实收 → 自动计算差异 `diff = cash_actual − cash_expected`
- 提交交班 → 写入 `vk-shift`，生成交班单（交班时间、操作人、汇总数据、差异、备注）
- 历史交班记录可查询

### 4.7 今日日报（`pages/report/today`，店长权限）

- 营业汇总：消费总额、优惠总额、实收总额、开单数、结账数
- 项目销量排行（按 `vk-order-item` 分组统计）
- 技师上钟数排行（按明细分组统计）
- 支付方式构成（按 `vk-order-pay` 分组统计）
- 数据接口：`sys.report/today`

## 6. 接口设计（云对象）

统一约定：

- 目录：`router/service/manager/`，文件名 `sys.` 前缀，含 `isCloudObject: true`
- 前端调用：`vk.callFunction({ url: 'manager/sys.xxx.yyy' })` 或 `vk.importObject('manager/sys.xxx')`
- 返回约定：成功 `code: 0`，失败非零 `code` + `msg`
- 数据库操作：一律 `vk.baseDao.*` / `vk.daoCenter.<xxx>Dao.*`，分组统计用 `vk.baseDao.selects`，**禁止 `db.collection()`**

## 8. 关键业务规则

1. **防并发（状态机）**：开单、上钟/落钟、结账、交班均采用「事务 + `whereJson` 状态条件更新 + `updateAndReturn`」，条件不满足即返回失败，杜绝重复开单、重复结账、并发抢单
2. **状态机**
   - 房间：空闲 →（开单）占用 →（结账）打扫 →（清洁）空闲
   - 账单：消费中 →（结账）已结账；消费中 →（全部明细取消）已取消
   - 明细：待上钟 →（上钟）上钟中 →（落钟）已完成；待上钟 →（取消）已取消
   - 技师：排队 →（被派钟）上钟中 →（落钟）排队队尾
3. **排钟公平性**：轮钟按 `queue_pos` 取首位派工；点钟 `queue_type=1` 可越过队列直接派工；落钟技师自动回队尾
4. **一口价快照**：开单时把项目名称、价格写入 `vk-order-item`，后续项目改价不影响历史账单
5. **到钟提醒**：前端以 `clock_start + duration` 计算倒计时，到点弹窗提醒；技师加钟后重算
6. **房态实时**：首页 10–15s 轮询 `sys.room/getBoard`，页面 onShow 立即刷新
7. **金额校验**：结账时服务端重算金额，不信任前端提交的金额；优惠需店长权限
8. **操作留痕**：结账、交班、优惠等关键操作记录操作人（`open_uid`/`pay_uid`/`close_uid`）
